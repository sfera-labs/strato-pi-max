# Compute Module 5 SD Card Compatibility

The Compute Module 5 features a high-speed SD interface. Some SD cards capable of operating at these higher speeds may experience compatibility issues when used through the Strato Pi Max XL SD matrix.

To ensure reliable operation, the high-speed SD modes must be disabled when an SD card is used with Strato Pi Max XL:

* **OS configuration** is required whenever the SD card is used as storage, including when booting the operating system from the SD card.
* **Bootloader configuration** is additionally required when the Compute Module must boot directly from an SD card.

## OS Configuration

Before using an SD card with Strato Pi Max XL, modify the Device Tree used by the operating system to disable the unsupported high-speed SD modes.

This can be done by mounting the SD card on a Linux host or by booting a Raspberry Pi from the SD card.

The procedure below assumes that you are running Raspberry Pi OS from the SD card.

The standard Device Tree Blob (DTB) files are stored in the boot partition, which is normally mounted at:

```text
/boot/firmware/
```

By default, Raspberry Pi OS uses:

* `bcm2712-rpi-cm5-cm5io.dtb` for the Compute Module 5
* `bcm2712-rpi-cm5l-cm5io.dtb` for the Compute Module 5 Lite

### 1. Decompile the Device Tree

Decompile the DTB corresponding to the Compute Module installed in your Strato Pi Max. Warnings generated by `dtc` can be ignored.

For a CM5:

```bash
dtc -I dtb -O dts \
    /boot/firmware/bcm2712-rpi-cm5-cm5io.dtb \
    -o ~/stratopimax-cm5-sd-compat.dts
```

For a CM5 Lite:

```bash
dtc -I dtb -O dts \
    /boot/firmware/bcm2712-rpi-cm5l-cm5io.dtb \
    -o ~/stratopimax-cm5-sd-compat.dts
```

### 2. Locate the `sdio1` controller

Find the Device Tree node corresponding to `sdio1`:

```bash
grep 'sdio1 =' ~/stratopimax-cm5-sd-compat.dts
```

Example output:

```text
sdio1 = "/soc@107c000000/mmc@fff000";
```

### 3. Edit the Device Tree source

Open the DTS file:

```bash
nano ~/stratopimax-cm5-sd-compat.dts
```

Locate the node identified in the previous step. In `nano`, you can use <kbd>Ctrl</kbd>+<kbd>W</kbd> and search for `mmc@fff000`.

The node will look similar to the following:

```dts
mmc@fff000 {
        compatible = "brcm,bcm2712-sdhci", "brcm,sdhci-brcmstb";
        reg = <0xfff000 0x260 0xfff400 0x200>;
        reg-names = "host", "cfg";
        interrupts = <0x00 0x111 0x04>;
        clocks = <0x08>;
        clock-names = "sw_sdio";
        mmc-ddr-3_3v;
        pinctrl-0 = <0x09 0x0a>;
        pinctrl-names = "default";
        vqmmc-supply = <0x0b>;
        vmmc-supply = <0x0c>;
        bus-width = <0x08>;
        sd-uhs-sdr50;
        sd-uhs-ddr50;
        sd-uhs-sdr104;
        mmc-hs200-1_8v;
        broken-cd;
        supports-cqe = <0x01>;
        status = "okay";
        phandle = <0x75>;
};
```

### 4. Disable the UHS SD modes

Remove the `sd-uhs-*` properties. The resulting node should look similar to:

```dts
mmc@fff000 {
        compatible = "brcm,bcm2712-sdhci", "brcm,sdhci-brcmstb";
        reg = <0xfff000 0x260 0xfff400 0x200>;
        reg-names = "host", "cfg";
        interrupts = <0x00 0x111 0x04>;
        clocks = <0x08>;
        clock-names = "sw_sdio";
        mmc-ddr-3_3v;
        pinctrl-0 = <0x09 0x0a>;
        pinctrl-names = "default";
        vqmmc-supply = <0x0b>;
        vmmc-supply = <0x0c>;
        bus-width = <0x08>;
        mmc-hs200-1_8v;
        broken-cd;
        supports-cqe = <0x01>;
        status = "okay";
        phandle = <0x75>;
};
```

### 5. Recompile the Device Tree

Compile the modified DTS file into a DTB:

```bash
dtc -I dts -O dtb \
    ~/stratopimax-cm5-sd-compat.dts \
    -o ~/stratopimax-cm5-sd-compat.dtb
```

Warnings generated by `dtc` can be ignored.

### 6. Install the modified DTB

Copy the generated file to the boot partition:

```bash
sudo cp ~/stratopimax-cm5-sd-compat.dtb /boot/firmware/
```

### 7. Select the modified Device Tree

Edit:

```text
/boot/firmware/config.txt
```

and add:

```text
device_tree=stratopimax-cm5-sd-compat.dtb
```

The operating system will now use the modified Device Tree, with the unsupported UHS SD modes disabled.

> **Note:** The same OS configuration is required whether the SD card is used as the boot device or only as a storage device.

## Bootloader Configuration

The OS Device Tree configuration affects SD card operation **after the operating system has started**. If the Compute Module must **boot directly from an SD card**, the bootloader must also be configured to avoid the unsupported high-speed SD modes.

First, ensure that the CM5 bootloader is updated to a version that supports the required configuration. This must be done while booting the Strato Pi Max from an alternative boot device, such as NVMe storage.

Then add the following property to the bootloader configuration:

```text
SD_QUIRKS=0x1
```

This configuration ensures that the bootloader also applies the required SD interface compatibility settings during the boot process.

For more information, refer to the official [Raspberry Pi bootloader configuration documentation](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html?utm_source=chatgpt.com#raspberry-pi-bootloader-configuration).
